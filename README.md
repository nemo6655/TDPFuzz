# TDPFuzz User Guide

This repository contains the source code of the replication package of the paper "LLM-driven Two-Dimensional Parallel Fuzzing Framework for Stateful Network Protocols ."




## 1. Direct Execution via Python Script

This is the most basic way to run the tool, suitable for development debugging or running directly on the host/container.

**Command Format:**
```bash
ELMFUZZ_RUNDIR=<preset_dir> python ./cli/main.py tdnet -T <fuzzer_name> <test_object> -n <runs>
```

**Parameters:**
- `ELMFUZZ_RUNDIR`: Environment variable, specifies the directory for preset configuration files.
- `-T <fuzzer_name>`: Specifies the Fuzzer name to use, e.g., `tdpfuzzer.tdpfuzzer`.
- `<test_object>`: Test target name (e.g., `exim`, `live555`, `forkeddaapd`, `kamailio`, `proftpd`, `pureftpd`).
- `-n`: Number of runs.

**Example:**
Run `exim` test 5 times:
```bash
ELMFUZZ_RUNDIR=preset/exim python ./cli/main.py tdnet -T tdpfuzzer.tdpfuzzer exim -n 5
```

## 2. Running Fuzz via Docker (tdpfuzz_exec.sh)

This script encapsulates the Docker startup command, used to execute Fuzz tasks in a clean container environment and save results to a specified directory.

**Command Format:**
```bash
./tdpfuzz_exec.sh <image_name> <test_number> <data_path> <fuzzer_name> <test_object>
```

**Parameters:**
- `<image_name>`: Docker image name.
- `<test_number>`: Test number (used to distinguish different experimental rounds).
- `<data_path>`: Host path to save result data.
- `<fuzzer_name>`: Fuzzer name (supports `tdpfuzzer.tdpfuzzer`, `tdpfuzzer.tdpfuzzer_noss`, `tdpfuzzer.tdpfuzzer_nosm`).
- `<test_object>`: Test target.

**Example:**
```bash
./tdpfuzz_exec.sh tdpfuzz:latest 1 /home/data/test_results tdpfuzzer.tdpfuzzer exim
```

## 3. Generating and Calculating Coverage (tdpfuzz_exec_test_cov.sh)

This script is mainly used to process results generated by Fuzz runs, extract data, and start the corresponding coverage generation container to calculate code coverage (`cov_over_time.csv`).

**Command Format:**
```bash
./tdpfuzz_exec_test_cov.sh <image_name> <test_number> <data_path> <fuzzer_name> <test_object>
```

**Parameters:**
- Similar to `tdpfuzz_exec.sh`, the main difference is that this script executes subsequent coverage analysis logic.
- This script is typically used to process data packages (`.tar.xz`) generated after Fuzzing, extract `replayable-queue` and re-execute the target program to utilize coverage statistics.

**Example:**
```bash
./tdpfuzz_exec_test_cov.sh tdpfuzz:latest 1 /home/data/test_results tdpfuzzer.tdpfuzzer exim
```

## 4. Parallel Coverage Statistics (para_cov.sh)

This script is designed for parallel environments, capable of batch processing multiple Fuzz result archives in a specified directory. It merges all test cases (seeds) extracted from the archives into a single directory, then starts the coverage statistics container for unified calculation.

**Command Format:**
```bash
./para_cov.sh <test_object> <data_dir>
```

**Parameters:**
- `<test_object>`: Test target (e.g., `live555`, `exim`, etc.).
- `<data_dir>`: Data directory containing multiple Fuzz result archives (`.tar.gz` or `.tar.xz`).

**Script Functionality:**
1.  Automatically extracts and merges all found `replayable-queue` contents into `<data_dir>/merged-cov/replayable-queue`.
2.  Starts the Docker container for the corresponding target (e.g., `exim:latest`).
3.  Mounts the merged directory and runs `cov_script` to generate `cov_over_time.csv`.
4.  Moves the final CSV file to the root of `<data_dir>`.

## 5. SPCM Analysis Tool (spcm.sh)

`spcm.sh` is used to automate SPCM (State-Protocol Code Coverage Metric) analysis tasks. It supports parallel processing and can invoke Docker for coverage statistics.

**Command Format:**
```bash
./spcm.sh -t <target> [-d <target_dir>] [-r <run_dir>] [-c] [-x] [-j <jobs>]
```

**Parameters:**
- `-t <target>`: **(Required)** Target name (e.g., `exim`, `live555`).
- `-d <target_dir>`: Target data directory (default: `$BASE_PATH/<target>`).
- `-r <run_dir>`: Run directory path (default: auto-detected in `<target_dir>/run1`).
- `-c`: **Enable coverage statistics**, this will start the container to run `cov_script`.
- `-x`: Clean old SPCM output directory before running.
- `-j <jobs>`: Max parallel jobs (default: 4).

**Example:**
Clean and analyze `live555`, while calculating coverage, using 8 parallel jobs:
```bash
./spcm.sh -t live555 -x -c -j 8
```
